# Nice to Have

Ideas that came up during sessions but are out of scope or belong to a later version. Each entry notes the feature it came from.

_Appended silently during sessions; reviewed by the customer when all features are done._

## Nominated by the customer

- **Subscription plans for salons** — tiered plans by number of branches, access to reports, etc. (would sit alongside or replace the commission model of feature 7/8; monetization beyond per-visit commission).
- **Profile for barber** — a barber-facing profile view (own rating, history, own availability). Note: feature 2 gives barbers a salon-owned profile with name/photo/rating, and feature 11 confirmed barbers have **no login** — so this would require the barber-login decision of feature 11 to be revisited.

## Proposed by the assistant (grounded in locked decisions)

- **Analytics / reports dashboard for salons** — visits per barber, peak hours, no-show rates, wait-time accuracy; a natural paid tier (ties into the subscription-plans idea).
- **Wait-time calibration** — learning real service durations vs the catalog estimate (feature 6) and adjusting expected wait; the queue math would stay honest as the salon's real timings drift from defaults.
- **Cross-salon barber career history** — cumulative ratings/badges across salons. Feature 2 explicitly rejected cross-salon identity ("new profile, no trace") — revisiting that decision if barbers want a portable reputation.
- **Category-breakdown salon ratings** — cleanliness, waiting time, price as separate sub-ratings (feature 10 said each barber/salon rating is a single star+comment scale; this seeds richer comparison). *Already noted in feature 10's doc.*
- **Favorites** — customer pins a favorite barber/salon (reachable via feature 10's ranking and feature 2's barber profiles) so booking flows started quicker.
- **Branch-level dashboards per branch** — while feature 11 scopes each employee to one branch, a salon-level admin can switch branches; a dedicated per-branch screen with its own metrics (chair utilization, queue depth) is a future dashboard layer.
- **Bilingual app (Arabic / English)** — relevant for Egypt's market; nothing in the current model depends on language, so it's purely a localization effort.
